# revision-{version}.md 模板

## 约束

proposal-reviewer 必须遵守：
- **只读** proposal-{version}.md，不得修改
- 审查意见必须可追溯（指出具体章节/段落）
- 所有维度 ≥ 3 分 且 无 BLOCKER → 审查通过 → 写 revision-final.md

---

```markdown
# 审查报告 — proposal-{version}.md

## 总评

**审查结论**: [PASS / NEEDS REVISION]
**综合得分**: X.X / 5.0

## 逐维度评分

| 维度 | 得分 | 评语 |
|------|------|------|
| 需求覆盖度 | ?/5 | |

| 性能可量化 | ?/5 | |
| 方案完整性 | ?/5 | |
| 排期合理性 | ?/5 | |

> 评分细则见 `references/review_dimensions.md`

## 问题清单

### 问题 #1: {标题}
- **严重程度**: [BLOCKER / MAJOR / MINOR / SUGGESTION]
- **位置**: §{章节号} {章节名}

...

[列出方案中应该覆盖但遗漏的内容，如有]
```

---

## 严重程度定义

| 级别 | 含义 | 处理要求 |
|------|------|---------|
| **BLOCKER** | 方案存在致命缺陷，不可进入实施 | 必须修改后才能通过 |
| **MAJOR** | 方案存在重要缺陷，建议修改 | 强烈建议修改 |
| **MINOR** | 方案存在小问题 | 可选修改 |
| **SUGGESTION** | 优化建议 | 可选采纳 |
